## C01, held-out likelihood

Motivating question: the model fit the training data. What does
it say about data it never saw?

Start from zero. Five held-out points: -2.1, 1.9, -1.8, 2.2,
0.1. Model A (N(0, 4.25)) scores them at total loglik
-10.1073. Model B (N(2, 0.25)) scores -70.949. Model A wins by
60 nats. The point -2.1 decides it: A assigns -2.16 nats there,
B assigns -33.85, the largest single gap (31.68 nats). At 0.1, A
gives density 0.1933, B gives 0.0006. The held-out set punishes the model that left
probability mass off the data.

The idea: held-out likelihood is the honest score: the model
is judged on points it did not fit. Training likelihood always
favors the more flexible model. Held-out likelihood favors the
model that generalizes. The comparison needs the same held-out
set, the same units, and exact (not bound) numbers to be
decisive. With bounds, the ranking can flip inside the gap.

Computed example: -10.1073 versus -70.949 above. Per point: A
averages -2.02 nats, B averages -14.19. The gap is enormous
because B assigns near-zero density to the left-mode points.

Variables, units, shapes, assumptions: loglik in nats, summed
over the held-out set. Assumption: the held-out points are
drawn from the same law as the future data. Distribution shift
breaks the interpretation.

Mechanism: fit on train, score on held-out. The log is the
right scale: it rewards probability where data lands and
punishes overconfidence harshly.

Code:

    ll_A = np.sum(np.log(gauss(held, 0.0, std_true)))
    print(ll_A)  # -10.1073

Check: a model that memorized the training set scores
-training points perfectly and held-out points by its
smoothing. The gap between the two is the memorization
signal.

Cost: one density evaluation per held-out point. Cheap.

Alternatives: cross-validation (averages over splits).
Held-out once (simpler, noisier). Use CV when the set is
small.

Failure case: tuning on the held-out set. It becomes a
second training set and the score inflates. Lock it away.
Touch it once.

Research reading: model selection texts (background).
Falsifiable extension: split the toy data into train/half1/
half2. Fit A and B on train. Score on half1, then tune B's
variance on half1, then score on half2. Report how much of
the half1 gain survives to half2.

## C02, bound versus exact score

Motivating question: the VAE reports -1.8621 and the flow
reports -1.7371. Which model is better?

Start from zero. Data point y = 1.0 under the model N(0, 4).
Exact loglik: -0.5 log(2 pi x 4) - 1/8 = -1.7371. A VAE with
approximate posterior q = N(0.5, 1) reports the ELBO: exact
minus the gap KL(q||p) = 0.125, giving -1.8621. The VAE's true
likelihood could be -1.7371 (gap 0.125 of looseness) or -1.8621
(tight bound, worse model). The bound does not say which.

The idea: a bound is a one-sided promise. ELBO <= log p, always.
Comparing a bound against an exact number compares a floor
against a value: the floor can sit below a worse model's exact
score. Rankings need exact-versus-exact or bound-versus-bound
with the gaps labeled. The gap is itself a measurable object:
tighten q and watch the bound rise.

Computed example: exact -1.7371, bound -1.8621, gap 0.125
above. A second VAE with bound -1.80 could be better or worse
than the flow: its truth lies in [-1.80, infinity).

Variables, units, shapes, assumptions: nats. The gap is
KL(q||posterior) >= 0. Assumption: the bound is a valid ELBO.
An invalid "bound" (coding bug) can exceed the truth.

Derivation: log p = ELBO + KL(q||p(z|x)). The KL is the gap.
Tightening q shrinks it. At q = posterior the gap is 0.

Code:

    print(exact_1, bound_1)  # -1.7371 -1.8621

Check: the bound must never exceed an exact likelihood of the
same model on the same point. A violation is a bug.

Cost: the gap is measurable by importance weighting: more
samples tighten the estimate.

Alternatives: exact models (no gap). Tighter bounds (IWAE).
Use exact models when the ranking must be decisive.

Failure case: "our VAE beats their flow" with bound -1.70
versus exact -1.7371. The VAE's truth could be -1.65 or
-1.70. The claim overreaches the evidence.

Research reading: variational bounds texts (background).
Falsifiable extension: none at this level. The claim is
arithmetic with a worked gap.

## C03, mode coverage

Motivating question: the truth has two modes. How many did the
model find?

Start from zero. Radius 1.0 around each mode. Model A samples:
at least one sample lands within 1 of -2 and within 1 of 2.
Coverage 2/2 = 1.0. Model B samples: all near 2. Coverage 1/2
= 0.5. The left mode is absent. No likelihood was needed:
just samples and a ruler.

The idea: mode coverage counts the data modes the model can
produce. It is a recall-style measure (C04) specialized to
modes. It needs a definition of "mode" (a peak, a cluster, a
class) and a radius. On real data, modes are classes or
clusters from a reference labeling. The measure is crude and
honest: it asks the one question likelihood averages away.

Computed example: 1.0 versus 0.5 above, from 4,000 seed-13
samples each.

Variables, units, shapes, assumptions: the radius is a choice
(1.0 here). Assumption: the reference modes are known. On real
data they come from labels or clustering, each with its own
error.

Mechanism: sample, assign each sample to the nearest mode,
count covered modes. The threshold "at least one sample" can
be hardened to "at least 5 percent of samples."

Code:

    rec_B = (near_mode(samp_B, -2).any() + near_mode(samp_B, 2).any()) / 2
    print(rec_B)  # 0.5

Check: the covering model must score 1.0. If it does not, the
radius is too small or the sample count too low.

Cost: thousands of samples plus nearest-mode assignment.
Cheap.

Alternatives: likelihood-based mode tests (need densities).
Human inspection (gold standard, slow). Use coverage as the
cheap automatic check.

Failure case: a radius so large that one mode's ball covers
both. Coverage reads 1.0 for every model. The radius must be
smaller than the mode separation.

Research reading: mode coverage texts (background).
Falsifiable extension: sweep the radius in (0.25, 0.5, 1.0,
2.0) for model B. Report coverage versus radius. Confirm it
jumps to 1.0 only when the radius bridges the modes.

## C04, sample precision/recall

Motivating question: the samples look good. Are they the right
samples?

Start from zero. Define the data manifold as within 1.0 of
either mode. Precision: fraction of model samples on the
manifold. Recall: fraction of modes with samples (C03).
Model A: precision 0.4708 (its blur spreads samples off the
manifold), recall 1.0. Model B: precision 0.9555 (sharp on
its mode), recall 0.5. Figure u08_f02_precision_recall.png
shows the split.

The idea: precision measures quality (are the samples
plausible), recall measures coverage (is anything missing).
One without the other lies: B is precise and incomplete, A
is complete and sloppy. The pair is the minimal honest
summary of sample quality. On real data the manifold is
estimated (k-NN balls around reference samples), which adds
its own bias: the estimator favors models that stay near the
reference set.

Computed example: the four numbers above, from 4,000 samples
each at seed 13.

Variables, units, shapes, assumptions: the radius defines the
manifold. Assumption: the reference set covers the truth. A
thin reference set underestimates recall for every model.

Mechanism: build k-NN balls around reference samples (the
manifold estimate). Precision: fraction of model samples
inside any ball. Recall: fraction of reference samples with
a model sample inside their ball.

Code:

    prec_B = np.mean(near_mode(samp_B, -2) | near_mode(samp_B, 2))
    print(prec_B)  # 0.9555

Check: a model that copies the reference set scores precision
1 and recall 1: the memorization trap (C06). The pair needs
the NN test beside it.

Cost: O(n m) distances naive, less with trees. Thousands of
samples each side.

Alternatives: FID (moments only). Human ratings (expensive).
Use precision/recall as the default sample summary.

Failure case: reporting precision alone. The collapsed GAN
(U05-C09) scores precision 1.0 and recall 0.5. Precision
alone crowns it.

Research reading: precision/recall for generative models
(background).
Falsifiable extension: vary the radius and plot the
precision-recall curve for A and B. Confirm B dominates on
precision and A on recall at every radius.

## C05, FID limitations

Motivating question: a popular score says the model is
perfect. The samples say otherwise. Who is right?

Start from zero. The truth is bimodal with mean 0 and variance
4.25. Model A is N(0, 4.25): same mean, same variance, one
hump. The 1-D FID: (m1 - m2)^2 + (s1 - s2)^2 = 0 + 0 = 0.
Perfect score. The shapes share nothing beyond two moments.
Figure u08_f03_fid_limitation.png shows the two curves: two
modes against one.

The idea: FID compares Gaussian fits to feature
distributions: means and covariances only. Anything beyond
second moments is invisible: bimodality, skewness, tail shape,
manifold structure. A model that matches moments and misses
everything else scores 0. Real FID uses Inception features,
which adds two more failure layers: the features may miss
what matters (medical images, 1-D toys), and the Gaussian fit
may miss the feature law. FID is a useful smoke test, not a
verdict.

Computed example: FID = 0.0000 above, with the true law
bimodal and the model unimodal. The score is maximally wrong.

Variables, units, shapes, assumptions: FID >= 0, lower is
better. Assumption: the feature law is near-Gaussian. Bimodal
features break it.

Mechanism: embed samples, fit a Gaussian to each embedding
set, compute the Frechet distance between the Gaussians. Three
approximations: the embedding, the Gaussian fit, the distance.

Code:

    mu_true, mu_A = 0.0, 0.0
    std_A = np.sqrt(4.25)  # model A = N(0, 4.25)
    fid = (mu_true - mu_A) ** 2 + (std_true - std_A) ** 2
    print(fid)  # 0.0

Check: A matches the truth's mean and variance, so both terms
vanish. FID = 0 exactly, while the shapes differ completely.

Cost: one Inception pass per sample plus the covariance fit.
Thousands of samples needed for a stable covariance.

Alternatives: precision/recall (sees modes). MMD with a
characteristic kernel (sees all moments). Human evaluation.
Use FID for iteration, never for the final claim alone.

Failure case: optimizing FID directly. The model learns the
Inception features, not the data. The score improves. The
samples do not.

Research reading: FID critique texts (background).
Falsifiable extension: construct three 1-D models with FID =
0 against the truth (Gaussian, uniform with matched moments,
three-point discrete with matched moments). Show their
samples differ wildly. Report the trio as the counterexample.

## C06, memorization

Motivating question: the samples look perfect. Are they new?

Start from zero. 50 training points from the truth. Model C
samples training points plus noise of scale 0.01. Mean
nearest-neighbor distance to the training set: 0.0066. Model
A's samples: 0.4666. The memorizer's samples sit on top of
the training data. Figure u08_f04_memorization.png shows the
two distance histograms: the memorizer's pile at zero, model
A's spread out.

The idea: memorization is the model returning its training
data. Likelihood cannot see it: a memorizer with slight
smoothing scores held-out points near training points well.
The nearest-neighbor test sees it directly: for each sample,
find the closest training point. A pile at zero distance is
the fingerprint. The test needs the training set, which
external evaluators may not have: another reason to distrust
single-number leaderboards.

Computed example: 0.0066 versus 0.4666 above, 400 samples
each at seed 13.

Variables, units, shapes, assumptions: distance in data units.
Assumption: the training set is available to the evaluator.
Without it, use a held-out split as a proxy reference.

Mechanism: sample, compute min distance to the training set,
histogram. Compare against a baseline model's histogram. The
memorizer's histogram spikes at zero.

Code:

    nn = np.mean([np.min(np.abs(train - s)) for s in mem_samp])
    print(nn)  # 0.0066

Check: a model sampling from the true law must show NN
distances like model A's, not like the memorizer's. Calibrate
on the truth first.

Cost: O(n x m) distances. Fine at thousands.

Alternatives: membership inference attacks (formalize the
test). Likelihood ratios train versus held-out (needs
densities). Use the NN histogram as the cheap screen.

Failure case: a test set that overlaps the training set.
Then every model looks like a memorizer. Deduplicate first.

Research reading: memorization in generative models
(background).
Falsifiable extension: vary the memorizer's noise scale in
(0.001, 0.01, 0.1, 0.5). Plot mean NN distance versus scale.
Find the scale where the test stops flagging it.

## C07, compute-matched baseline

Motivating question: the big model wins. Did the idea win, or
the budget?

Start from zero. Model A has 1,000 parameters, model B has
100,000. B wins on every metric. The comparison says nothing
about the architectures: B had 100x the budget. The honest
comparison fixes the budget: same parameters, same training
flops, same sampling cost, then compare. If B still wins at
matched budgets, the idea earned it.

The idea: compute matching separates ideas from resources.
Match training compute (flops), parameter count, and inference
cost separately: a model can win training-matched and lose
inference-matched. Report all three budgets. The baseline
must be strong: a weak baseline flatters any idea. Tune the
baseline as hard as the proposal.

Computed example: the toy protocol. Budget: 1,000 parameters,
10,000 training samples, 4,000 evaluation samples. Both A and
B fit inside it. The reported gaps (60 nats held-out, 0.5
recall) are then about the models, not the money.

Variables, units, shapes, assumptions: flops, parameter
counts, wall time. Assumption: the budgets are actually
binding. A budget nobody hits constrains nothing.

Mechanism: fix the budget, tune each model within it,
evaluate on frozen metrics. The tuning effort must be
symmetric: asymmetric tuning is the most common cheat.

Code:

    budget = {"params": 1000, "train_n": 10000, "eval_n": 4000}
    print(budget)

Check: both models must actually use the full budget. An
under-tuned baseline is a strawman.

Cost: the protocol multiplies the work: every baseline gets
tuned. Budget for it.

Alternatives: scaling-law comparisons (fit the tradeoff
curve). Fixed-wall-time races (pragmatic, noisy). Use
matched budgets as the minimum honest bar.

Failure case: "our method beats the baseline" where the
baseline ran with default hyperparameters. The idea did not
win. The tuning did.

Research reading: fair comparison texts (background).
Falsifiable extension: none at this level. The claim is a
protocol.

## C08, synthetic ground truth

Motivating question: on real data the truth is unknown. Where
can we test against a known answer?

Start from zero. Draw 5,000 points from the known mixture.
Fit the moment-matched Gaussian. Recovered mean -0.0317,
variance 4.2352. Truth: 0 and 4.25. The recovery error is
sampling noise, and we know it exactly because we wrote the
truth. On real data this check is impossible: the truth is
what the method must learn.

The idea: synthetic ground truth is the laboratory. The data
law is chosen by the experimenter, so every estimator can be
scored against the right answer: bias, variance, coverage of
intervals. Methods graduate from synthetic to real only after
passing here. A method that fails on a known mixture will not
magically work on images.

Computed example: recovered -0.0317 and 4.2352 versus truth 0
and 4.25, at seed 13 with n = 5000. The standard error of the
mean is sqrt(4.25/5000) = 0.029: the -0.0317 sits within 1.1
standard errors. Consistent.

Variables, units, shapes, assumptions: n = 5000, seed 13.
Assumption: the synthetic law exercises the phenomenon of
interest. A toy that is too easy proves nothing.

Mechanism: choose the truth, sample, run the method, compare
against the known answer. Repeat over seeds for uncertainty
(C09).

Code:

    print(syn.mean(), syn.var())  # -0.0317 4.2352

Check: the recovery must land within a few standard errors of
the truth. Far outside means a bug, not bad luck.

Cost: one synthetic dataset per phenomenon. Cheap.

Alternatives: real data with proxy labels (noisy truth).
Theory alone (no empirical check). Use synthetic first,
always.

Failure case: a method tuned on the synthetic truth's exact
form (e.g. knowing the mode count). It will not transfer.
Keep the method blind to the truth's parameters.

Research reading: simulation-based method validation
(background).
Falsifiable extension: none at this level. The claim is a
worked validation.

## C09, uncertainty

Motivating question: the metric reads 0.4835. How much does
that number wobble?

Start from zero. Model A precision over 5 seeds (100-104):
mean 0.4835, std 0.0115. The honest report: 0.484 +/- 0.012.
A competing model at 0.490 is not better: the gap 0.0065 sits
inside the noise. Without the error bar, the leaderboard lies.

The idea: every metric is a random variable over seeds, data
splits, and sampling noise. Report the mean and the standard
error, or a confidence interval. The number of seeds is a
choice: 5 is the minimum for a std, 10 is better. The seed
range must be fixed before running: picking seeds after
seeing results is cherry-picking.

Computed example: 0.4835 +/- 0.0115 above. Two standard
errors: +/- 0.023. A gap smaller than that is noise.

Variables, units, shapes, assumptions: seeds 100-104, n =
2000 per seed. Assumption: the seeds are independent draws.
Reusing one seed everywhere understates the variance.

Mechanism: run, collect, mean, std. The standard error of the
mean is std/sqrt(k). Report it.

Code:

    print(vals.mean(), vals.std())  # 0.4835 0.0115

Check: the std must shrink roughly as 1/sqrt(n) with more
samples per seed. If it does not, something structural varies.

Cost: k runs instead of 1. Budget 5x the evaluation.

Alternatives: bootstrap over one run (cheaper, assumes the
run is representative). Bayesian intervals (needs a model).
Use multiple seeds as the default.

Failure case: the single-seed leaderboard. The winner is the
luckiest seed, not the best model. Every "state of the art"
without error bars is suspect.

Research reading: uncertainty reporting texts (background).
Falsifiable extension: none at this level. The claim is a
worked error bar.

## C10, falsification

Motivating question: the experiment succeeded. What would have
counted as failure?

Start from zero. Claim: "Model A covers both modes." Pre-register:
with 4,000 samples and radius 1.0, recall must be 1.0. If any
mode gets zero samples, the claim fails. Run: recall 1.0. The
claim survives. Now the sharp version: "Model B covers both
modes." Same protocol. Run: recall 0.5. The claim is falsified.
The experiment had teeth because the failure criterion was
written before the run.

The idea: falsification is the discipline of stating what
would prove you wrong, before you look. A hypothesis without
a failure criterion is a wish. Pre-registration (of the
metric, the threshold, the sample count) blocks
post-hoc storytelling: moving the goalposts after seeing the
data. Negative results are results: the falsified claim about
B is as informative as the surviving claim about A.

Computed example: the two pre-registrations above. B's 0.5
falsifies its claim cleanly.

Variables, units, shapes, assumptions: the protocol is fixed
before the run. Assumption: the failure criterion is sharp
enough to bite. A criterion every model passes tests nothing.

Mechanism: write the claim, the metric, the threshold, and
the sample size. Run once. Report the outcome against the
threshold. No re-runs until it passes.

Code:

    # pre-registered: recall == 1.0 with n=4000, r=1.0, or FAIL
    assert rec_B == 1.0, "claim falsified"  # raises: 0.5 != 1.0

Check: the criterion must be checkable from the logged
output alone. Vague criteria ("good coverage") are not
criteria.

Cost: the discipline costs nothing. The re-runs it prevents
save everything.

Alternatives: exploratory analysis (fine, but labeled as
such). Bayesian model comparison (different framework, same
honesty need). Use pre-registration for confirmatory claims.

Failure case: HARKing (hypothesizing after results are
known). The "prediction" matches the data because it was
written from the data. The test has no power.

Research reading: falsification and pre-registration texts
(background).
Falsifiable extension: none at this level. The claim is a
method with a worked example.

## C11, source-identity report

Motivating question: this course cites sources it has not
fully read. How is that reported honestly?

Start from zero. The source-identity report is a document with
one row per claimed source: the artifact ID, the canonical
link, what was inspected (overview, file listing, full text),
what was not, and which lesson leaves depend on it. This
course's report lives in source_manifest.md, and its gaps live
in source_gaps.md G1-G7. Every leaf in this course carries
PLANNED / SOURCE ATTRIBUTION PENDING because the report says
the artifacts were not fully inspected.

The idea: the report separates "the material is taught" from
"the material is sourced." A course can be mathematically
complete and attribution-incomplete at the same time: this
one is. The report makes the boundary checkable: a reader can
see exactly which artifact would close each gap. No silent
upgrades: a gap closes only when the inspection happens and
the row is updated.

Computed example: SRC-03 (the teaching repository): file
inventory fetched, notebooks not executed. Gap G5-G7 open.
Closing them needs cell-by-cell inspection, not a re-read of
the listing.

Variables, units, shapes, assumptions: one row per source.
Assumption: the report is updated when inspections happen.
A stale report is worse than none.

Mechanism: the report template. Fields: artifact ID,
canonical link, publisher, title, edition/date, access
status, inspection extent, extracted concepts, lesson mapping,
remaining gaps. Fill it per artifact. Review it quarterly
(currentness.md).

Code:

    print("see source_manifest.md SRC-01..SRC-05, source_gaps.md G1-G7")

Check: every PLANNED leaf must have a gap row pointing at the
missing inspection. An unattributed leaf with no gap row is a
reporting bug.

Cost: the report is written once and maintained. Cheap.

Alternatives: no report (the gaps go silent). Inline
citations only (no inspection log). Use the full report:
provenance is a first-class artifact.

Failure case: citing the repository as "the source" after a
file listing. A listing is not an inspection. The report must
say what was actually read.

Research reading: provenance practice texts (background).
Falsifiable extension: none at this level. The claim is a
reporting standard with the course's own report as the
example.

## C12, role gap map

Motivating question: the course is done. Who is it for, and
where does it stop?

Start from zero. The role gap map (role_gap_map.md) has one
section per target role: research scientist, research
engineer, FDE, AI/ML engineering, LLM engineering, MLOps,
agent engineering. Each section names what the course serves
and where it honestly does not. Example: research engineer is
served on numerics and reproduction, with the gap "no GPU
profiling or distributed training, CPU toys only."

The idea: the map turns "this course teaches generative
models" into per-role truth. Each role has different gates
(the prompt lists them: assumptions and identifiability for
research, discovery and handoff for FDE, artifacts and drift
for MLOps). The course serves some gates per role and misses
others. The map states both. Courses alone do not replace
DSA, distributed systems, domain expertise, collaboration, or
research experience: the map says so explicitly.

Computed example: the research-engineer row above. The FDE
row: served on discovery framing and acceptance gates
(capstone 2), gap on client engagement simulation.

Variables, units, shapes, assumptions: one section per role.
Assumption: the role gates come from the prompt's role list.
New roles need new rows.

Mechanism: for each role, list the gates, mark each served or
gap with the evidence (unit, concept, capstone), and state the
residual plainly. Review when the course grows.

Code:

    print("see role_gap_map.md, seven roles, served/gap per gate")

Check: every role in the prompt must have a section. A role
with only "served" and no gaps is suspicious: check harder.

Cost: one honest pass per course version. Cheap.

Alternatives: a single "who is this for" paragraph (hides the
gaps). Per-role marketing (inverts the honesty). Use the gap
map: it is the course's contract with the learner.

Failure case: the map claims MLOps deployment coverage from
toy scripts. The gap row must say: no production artifacts,
no CI/CD, no drift monitoring. Overclaiming the map voids the
course's honesty banner.

Research reading: curriculum design texts (background).
Falsifiable extension: none at this level. The claim is a
reading guide with the course's own map as the example.

### Breadth recall (6)

B1. Define held-out likelihood. Compute it for model A on the
5-point set.
B2. State the ELBO gap identity and evaluate the toy gap.
B3. Define mode coverage and compute it for model B.
B4. Define sample precision and recall. Report all four toy
numbers.
B5. Construct the FID counterexample from this unit.
B6. State the memorization test and report the two NN
distances.

### Deep ladders (2 ladders x 5 follow-ups)

L1 (honest scoring, end to end): define held-out likelihood.
Compute A versus B. Explain why B loses. Separate the bound
from the exact number. State the ranking rule for mixed
comparisons.
L2 (samples under suspicion, end to end): define precision
and recall. Compute all four numbers. Show FID = 0 on the
wrong shape. Run the NN test. Explain why one metric never
suffices.

### Analytical exercises (2)

A1. Prove the 1-D FID formula for Gaussians and show it is 0
for model A versus the truth's moments. Then construct a
discrete 3-point law with the same mean and variance.
A2. Derive the standard error of the recovered mean in C08
and confirm the -0.0317 sits within 1.1 standard errors.

### Implementation and debug (1)

D1. A model reports FID 12.3 (good) but human raters reject
the samples. The features are Inception, the data are
medical X-rays. Name the bug, give the fix, and state the
test that catches it. (Keys file holds the diagnosis.)

### Changed-constraint scenarios (2)

T1. The training set cannot leave the hospital. Redesign
evaluation without it and state what you lose.
T2. The leaderboard allows one number. You must pick it.
Choose, defend the choice, and state what it hides.

### Research critique (1)

R1. "Our model has the best FID, so it is the best generative
model." Attack this claim with two arguments from this unit
and propose the fair experiment.
