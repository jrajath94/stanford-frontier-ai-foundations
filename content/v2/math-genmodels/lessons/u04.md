## C01, invertibility

Motivating question: which maps can be undone, and why do flows
need exactly those?

Start from zero. f(z) = 2z + 1 undoes cleanly: f^-1(x) = (x -
1)/2. Check: f^-1(3) = 1.0, and f(1.0) = 3. One input per output,
one output per input. Now g(z) = z^2: g(1) = 1 and g(-1) = 1. Two
inputs land on one output. No inverse exists. Figure
u04_f01_invertibility.png shows the fold against the clean line.

The idea: a map is invertible when it is one-to-one and onto: every
y has exactly one x with f(x) = y. Flows compose invertible layers.
The inverse direction evaluates densities. The forward direction
draws samples. A non-invertible layer breaks the density direction
silently: two preimages mean the change-of-variables formula needs
a sum the code does not compute.

Computed example: f^-1(3) = 1.0 above. For the coupling layer,
inversion is by construction: x1 = y1, x2 = (y2 - t(y1)) /
s(y1). At (0.5, -0.75): x2 = (-0.75 - 0.5) / 1.25 = -1.0. Exact
recovery, verified to 1e-12 in the script.

Variables, units, shapes, assumptions: f: R^D -> R^D. The inverse
has the same shape. Assumption: s(v) never hits zero, else the
division in the inverse fails. Here s(v) = 1 + v^2 >= 1 always.

Mechanism: design layers whose inverse is algebraic, not
numerical. Affine coupling, additive coupling, and triangular maps
all invert in closed form. Never rely on a numerical solver inside
a flow layer.

Code:

    def fwd(z): return 2*z + 1
    def inv(x): return (x - 1)/2
    print(inv(3.0), fwd(inv(3.0)))  # 1.0 3.0

Check: fwd(inv(x)) == x and inv(fwd(z)) == z on a grid. Any
mismatch is a bug, not noise.

Cost: O(D) per direction for coupling layers. The design goal is
cheap both ways.

Alternatives: non-invertible generators (GANs, VAEs). They sample
cheaply and give up exact densities. Use them when the density is
not needed.

Failure case: a learned "inverse" that is only approximate. The
density evaluation then uses the wrong preimage and the likelihood
is wrong with no error raised. Test round-trips, never trust them.

Research reading: flow architecture texts (background).
Falsifiable extension: none at this level. The claim is
definitional.

## C02, determinant volume

Motivating question: a linear map stretches space. By how much?

Start from zero. A = [[2, 0], [0, 0.5]]. Its determinant is 2 x 0.5
= 1.0. The unit square maps to a 2-by-0.5 rectangle: stretched in
x, squeezed in y, area unchanged. B = [[2, 0.5], [0, 2]] has
determinant 4.0. The unit square maps to a parallelogram with area
4. Areas scale by |det|. Volumes in D dimensions scale the same
way.

The idea: the determinant is the signed volume scaling factor of a
linear map. |det| > 1 expands. |det| < 1 contracts. |det| = 1
preserves volume. det = 0 collapses a dimension: the map is not
invertible (C01). In a flow, the determinant corrects the density
for the stretching, so probability mass is conserved.

Computed example: det A = 1.0, det B = 4.0. A 1x1 square under A
keeps area 1. Under B it becomes area 4. The density on the image
is the base density divided by 4 at corresponding points.

Variables, units, shapes, assumptions: det is a scalar, unitless.
The map is D x D. Assumption: the map is linear here. Nonlinear
maps need the Jacobian at each point (C03).

Derivation: the determinant is the product of eigenvalues, and
eigenvalues are per-axis stretch factors. Their product is the
volume factor. For triangular matrices it is the product of the
diagonal (C06).

Code:

    print(np.linalg.det(np.array([[2.,0.],[0.,0.5]])))  # 1.0
    print(np.linalg.det(np.array([[2.,0.5],[0.,2.]])))  # 4.0

Check: det of a diagonal matrix is the product of the diagonal.
det(AB) = det(A) det(B): compose two maps and verify.

Cost: O(D^3) for a dense determinant. O(D) for triangular. This
cost gap is the reason coupling layers exist.

Alternatives: avoid determinants entirely (implicit models, U05).
Use them when exact likelihood is worth the architectural
constraint.

Failure case: a layer with det near zero. The map nearly collapses
a dimension. Densities blow up on the image. The condition number
1e12 toy in the script shows how fast this goes wrong.

Research reading: linear algebra texts on determinants (background).
Falsifiable extension: sample 10,000 points in the unit square,
push them through B, and measure the fraction landing in a target
region. Confirm it matches the base fraction divided by 4 within
noise.

## C03, Jacobian

Motivating question: the map is nonlinear. What plays the role of
the matrix?

Start from zero. f(z) = 2z + 1 has derivative 2 everywhere. Its
Jacobian is the 1x1 matrix [2]. For the coupling layer at (0.5,
-1): y1 = x1, y2 = x2 (1 + x1^2) + x1. Partial derivatives: dy1/dx1
= 1, dy1/dx2 = 0, dy2/dx1 = 2 x1 x2 + 1 = 2 x 0.5 x (-1) + 1 = 0,
dy2/dx2 = 1 + x1^2 = 1.25. Jacobian J = [[1, 0], [0, 1.25]].
Lower triangular. Determinant 1.25, matching the script's log-det
0.2231.

The idea: the Jacobian is the matrix of partial derivatives. It is
the local linear map at each point. The change-of-variables
formula uses |det J| at the point being transformed. For linear
maps the Jacobian is the matrix itself, constant everywhere. For
nonlinear maps it varies, and the volume correction varies with
it.

Computed example: the 2x2 Jacobian above at (0.5, -1). At (1, 2):
dy2/dx1 = 2 x 1 x 2 + 1 = 5, dy2/dx2 = 2. J = [[1, 0], [5, 2]].
Determinant 2. The volume factor changes across space.

Variables, units, shapes, assumptions: J is D x D. Entries are
derivatives dy_i/dx_j. Assumption: f is differentiable at the
point. Kinks (ReLU) break the formula there.

Derivation: first-order Taylor. f(x + dx) = f(x) + J dx. A small
cube of volume dV maps to a parallelepiped of volume |det J| dV.
That local fact, integrated, is the density transform.

Code:

    # Jacobian of the coupling layer at (0.5, -1) by hand
    J = np.array([[1.0, 0.0], [0.0, 1.25]])
    print(np.linalg.det(J))  # 1.25

Check: finite-difference the map and compare against the analytic
Jacobian. Agreement within 1e-6.

Cost: O(D^2) entries for a dense Jacobian, O(D^3) for its
determinant. Triangular structure cuts both (C06).

Alternatives: automatic differentiation gives Jacobian-vector
products without the full matrix. Use them when only the product
is needed.

Failure case: a Jacobian with a zero diagonal entry in a
triangular flow. The determinant is zero. The layer is not
invertible. Constrain the diagonal away from zero (exp or softplus
parameterization).

Research reading: multivariable calculus texts (background).
Falsifiable extension: none at this level. The claim is a
definition with a worked example.

## C04, density transform

Motivating question: the base law is N(0,1) and the map is x = 2z +
1. What is the density of x?

Start from zero. Probability mass is conserved. A small interval dz
around z maps to dx = 2 dz around x = 2z + 1. So p_x(x) dx = p_z(z)
dz, giving p_x(x) = p_z((x-1)/2) x |1/2|. At x = 1: p_z(0) = 0.3989,
times 0.5 = 0.1995. The curve is wider and lower than the base.
Its area is still 1: quadrature over [-9, 11] gives 0.999999.
Figure u04_f02_density_transform.png shows the base and the
stretched density with the conserved area.

The idea: the change-of-variables formula. p_x(x) = p_z(f^-1(x)) x
|det J_{f^-1}(x)|. Three ingredients: the base density, the
inverse map, the volume correction. Drop the correction and the
result does not integrate to 1. It is not a density. Every flow
likelihood is this formula applied layer by layer.

Computed example: p_x(1) = 0.1995 above. Also p_x(3) = p_z(1) x
0.5 = 0.2420 x 0.5 = 0.1210. The transformed law is N(1, 4):
mean 1, variance 4.

Variables, units, shapes, assumptions: p_z and p_x are densities
with 1/[x] units. The Jacobian determinant is unitless. Assumption:
f is a diffeomorphism: invertible with differentiable inverse.

Derivation: from the local volume fact in C03. P(x in A) = P(z in
f^-1(A)). Write both as integrals, substitute y = f(z), dy = |det
J| dz. The integrands must match, giving the formula.

Code:

    px1 = np.exp(-0.0)/np.sqrt(2*np.pi)/abs(2.0)
    print(px1)  # 0.1995

Check: quadrature of p_x over the line equals 1 within 1e-4. The
script asserts it.

Cost: one inverse evaluation plus one Jacobian determinant per
point per layer.

Alternatives: no transform (fit the base directly). Kernel density
(nonparametric, no invertibility needed). Use the transform when a
simple base plus a rich map beats a rich base.

Failure case: forgetting the |det| term. The "density" integrates
to 2 here, not 1. Likelihood comparisons against correct models
are then off by a constant per point, which compounds over the
dataset.

Research reading: probability texts on transformations (background).
Falsifiable extension: histogram 20,000 samples of x = 2z + 1 and
overlay p_x. The chi-square against the formula must pass.

## C05, coupling and autoregressive flows

Motivating question: how do we build a rich invertible map out of
cheap pieces?

Start from zero. Split x into (x1, x2). Leave the first half alone:
y1 = x1. Transform the second half with parameters from the first:
y2 = x2 x s(x1) + t(x1), with s(v) = 1 + v^2, t(v) = v. At (0.5,
-1): y1 = 0.5, y2 = -1 x 1.25 + 0.5 = -0.75. The inverse needs no
solver: x1 = y1, x2 = (y2 - t(y1)) / s(y1) = (-0.75 - 0.5) / 1.25 =
-1.0. The functions s and t can be neural nets. They never need
inverting, because they only appear as coefficients.

The idea: coupling layers get invertibility from structure, not
from the networks inside. Half the coordinates pass through
untouched and parameterize the transform of the other half. Stack
layers with alternating splits so every coordinate gets
transformed. Autoregressive flows push the idea further: each
coordinate depends on all previous ones, y_i = x_i x s_i(x_<i) +
t_i(x_<i). Same triangular structure, more expressive, with a
serial cost (C10).

Computed example: the forward and inverse numbers above. The
Jacobian at (0.5, -1) is [[1, 0], [0, 1.25]]: triangular because
y1 does not depend on x2.

Variables, units, shapes, assumptions: x in R^D, split into two
halves. s > 0 everywhere (here 1 + v^2). Assumption: the split is
fixed per layer and alternated across layers.

Mechanism: the untouched half is the conditioner. The transformed
half is affine in x2 with coefficients from x1. Affineness in the
transformed variables is what makes the inverse algebraic.

Code:

    def forward(x1, x2):
        return x1, x2 * (1 + x1**2) + x1
    def inverse(y1, y2):
        return y1, (y2 - y1) / (1 + y1**2)
    print(forward(0.5, -1.0))          # (0.5, -0.75)
    print(inverse(0.5, -0.75))         # (0.5, -1.0)

Check: round-trip recovers the input to 1e-12. Swap the split and
verify the other half transforms.

Cost: O(D) per layer per direction, plus the conditioner networks.

Alternatives: autoregressive layers (more expressive per layer,
serial sampling). Residual flows (weaker invertibility guarantee,
Lipschitz constraint). Use coupling for cheap sampling, MAF for
cheap density eval.

Failure case: never alternating the split. Half the coordinates
pass through every layer untouched. The model cannot correlate
them with the rest. The likelihood looks fine on marginals and
fails on joints.

Research reading: flow architecture texts (background).
Falsifiable extension: stack two coupling layers with the same
split versus alternating splits on a correlated 2-D toy. Measure
the held-out likelihood gap. Alternating should win.

## C06, triangular Jacobian

Motivating question: why is the determinant of a coupling layer
free?

Start from zero. The coupling Jacobian at (0.5, -1) is [[1, 0],
[0, 1.25]]. Lower triangular: zeros above the diagonal. Its
determinant is the product of the diagonal: 1 x 1.25 = 1.25.
Log-determinant: log 1.25 = 0.2231. No matrix factorization. Just
multiply D diagonal entries. Figure u04_f03_triangular_jacobian.png
contrasts the dense O(D^3) case with the triangular O(D) case.

The idea: triangular matrices have their eigenvalues on the
diagonal, so the determinant is the diagonal product. Coupling
layers are triangular by construction: y1 depends only on x1, y2
on (x1, x2), and so on. Autoregressive flows are triangular for
the same reason. The log-det of a stack of L layers is the sum of
D x L diagonal logs. Exact likelihood at linear cost.

Computed example: det = 1.25, log-det = 0.2231 above. For a stack
of 3 such layers with diagonal products 1.25, 0.8, 2.0: total
log-det = 0.2231 - 0.2231 + 0.6931 = 0.6931. Addition replaces
multiplication in log space.

Variables, units, shapes, assumptions: D diagonal entries per
layer, all nonzero. Assumption: the triangular structure is exact,
not approximate. A stray nonzero above the diagonal breaks the
shortcut silently.

Derivation: expand the determinant along the first row of a lower
triangular matrix. Only the diagonal entry survives. Induct on D.

Code:

    logdet = np.log(1.0) + np.log(1.25)
    print(logdet)  # 0.2231

Check: compare against np.linalg.det on the full 2x2. Agreement
within 1e-12.

Cost: O(D) per layer. The log-det of the full flow is a sum over
layers.

Alternatives: matrix-determinant lemma for low-rank updates
(O(D r^2)). Stochastic determinant estimators (unbiased, noisy).
Use the triangular shortcut whenever the architecture allows it.

Failure case: computing the determinant in linear space for a deep
stack. The product of 100 factors of 1e6 overflows float64 to inf
(C12). Always accumulate log-determinants.

Research reading: numerical linear algebra texts (background).
Falsifiable extension: none at this level. The claim is algebraic.

## C07, base density

Motivating question: the flow transforms something. What is the
something?

Start from zero. The base is the simple law the flow starts from:
z ~ N(0, I_2), the 2-D standard Gaussian. Its log-density at (0.5,
-1) is -0.5 x (0.25 + 1) - log(2 pi) = -0.625 - 1.8379 = -2.4629.
Every flow likelihood is this number plus the log-det corrections
of the layers. The base carries the "shape prior". The flow
carries the complexity.

The idea: separate the easy part from the hard part. The base is
trivial to sample and score. The flow is a deterministic map that
adds all the structure. Training moves structure from the base
into the map: the base stays fixed, the map learns. A Gaussian
base is the default because its log-density is one line and its
sampler is one call.

Computed example: log p_z(0.5, -1) = -2.4629 above. At the origin:
-0 - 1.8379 = -1.8379. The mode of the base. The flow will move
mass away from here as it learns.

Variables, units, shapes, assumptions: z in R^D. Log-density in
nats. Assumption: the base has full support (Gaussian does). A
base with bounded support restricts the flow's support (U01-C02).

Mechanism: the flow is a change of variables from the base. All
probability statements about y reduce to statements about z plus
Jacobians. The base is the coordinate system in which everything
is easy.

Code:

    log_pz = -0.5 * (0.5**2 + 1.0**2) - np.log(2*np.pi)
    print(log_pz)  # -2.4629

Check: the base density integrates to 1. Samples from the base look
like a round blob.

Cost: O(D) per evaluation. Negligible next to the flow.

Alternatives: mixture-of-Gaussians base (multimodal start,
harder). Learned base (more parameters). Uniform base (bounded
support). Use the Gaussian unless the data force otherwise.

Failure case: a base whose support misses a data region. The flow
is a diffeomorphism: it cannot create mass where the base has
none. The likelihood of real data underflows. Match supports first.

Research reading: flow texts on base choices (background).
Falsifiable extension: none at this level. The claim is
architectural.

## C08, exact likelihood

Motivating question: what is the model's exact score on one data
point?

Start from zero. The data point is y = (0.5, -0.75). Invert the
coupling layer: z = (0.5, -1.0). Score the base: log p_z(z) =
-2.4629. Subtract the log-det: log|det J| = 0.2231. Log-likelihood:
-2.4629 - 0.2231 = -2.6860 nats. Exact. No bound, no sampling, no
approximation. Figure u04_f05_chapter.png stores this number as
the unit's central result.

The idea: log p(y) = log p_z(f^-1(y)) - log|det J_{f^-1}(y)|. For
a stack of layers, chain the inverses and sum the log-dets. The
sign: the inverse map's Jacobian appears because density eval runs
backward. Forgetting the minus sign is the classic implementation
bug: it turns expansion into contraction.

Computed example: -2.6860 above. Compare the VAE bound from U03:
a bound of -3.0529 on a toy of similar scale. The flow's number is
exact. That exactness is the product being sold.

Variables, units, shapes, assumptions: y is one data point in
R^D. The log-likelihood is in nats. Assumption: the inverse and
the log-det are computed in log space (C12).

Derivation: the change-of-variables formula from C04, applied to
the inverse direction, in logs. For L layers: log p(y) = log p_z(z)
- sum_l log|det J_l|.

Code:

    log_py = log_pz - logdet
    print(log_py)  # -2.686

Expected output: -2.6860.

Check: the likelihood integrates to 1 over y (change of variables
both ways). Perturb y slightly and confirm the likelihood moves
smoothly.

Cost: one inverse pass plus D diagonal logs per layer. Same order
as sampling, opposite direction.

Alternatives: VAE bound (cheaper architecture, inexact). GAN
(no likelihood). Use the flow when the number itself matters:
model comparison, anomaly detection, compression.

Failure case: the sign error. Using + log|det| instead of -
reports -2.2398 instead of -2.6860. The model looks better than it
is. Always test the likelihood against a histogram on a toy where
the truth is known.

Research reading: flow texts on likelihood evaluation (background).
Falsifiable extension: sample 20,000 points from the flow, fit a
histogram, and compare the histogram heights against the exact
likelihood formula. Agreement validates both directions.

## C09, sampling direction

Motivating question: we can score data. How do we make new data?

Start from zero. Sampling runs the flow forward. Draw z ~ N(0,
I_2): say z = (0.5, -1.0). Apply the coupling layer forward: y1 =
0.5, y2 = -1 x 1.25 + 0.5 = -0.75. The new point (0.5, -0.75) is a
sample from the flow's law. Density eval ran the same layer
backward. One layer, two directions, two jobs.

The idea: forward = generation, inverse = scoring. The base noise
is the only randomness. Everything else is deterministic. This is
the reparameterization trick (U02-C08) as an architecture: the
model is a deterministic map from fixed noise to data.

Computed example: the sample (0.5, -0.75) above. Draw 20,000 base
samples, push them forward, histogram the outputs: the histogram
matches the exact density from C08. The script's affine check
(mean 1.0, variance 4.03 on 20,000 draws) is the 1-D version of
this test.

Variables, units, shapes, assumptions: z in R^D from the base.
y in R^D is the sample. Assumption: the base sampler is correct.
A biased base sampler corrupts every sample silently.

Mechanism: the pushforward. The flow maps the base law to the data
law. Sampling the base and pushing forward samples the data law.
No rejection, no chains, no burn-in.

Code:

    z = rng.standard_normal(2)
    y1 = z[0]
    y2 = z[1] * (1 + z[0]**2) + z[0]
    print(y1, y2)  # one fresh sample

Check: histogram of many samples against the exact density. A
chi-square test formalizes it.

Cost: one forward pass per sample. Parallel across samples.

Alternatives: MCMC sampling (no inverse needed, correlated
samples). Rejection (needs a proposal). Use the flow's forward
pass when it exists: it is the cheapest exact sampler available.

Failure case: sampling from the wrong direction. Running the
inverse on base noise does not sample the data law. It samples
nonsense. The direction matters and the code must label it.

Research reading: flow sampling texts (background). Falsifiable
extension: none at this level. The claim is procedural.

## C10, computational asymmetry

Motivating question: both directions are O(D). So which one is
actually cheap?

Start from zero. Coupling layers are parallel both ways: all of y2
computes at once from x1. Autoregressive flows are not. In a MAF
(Masked Autoregressive Flow), density eval is parallel: every y_i
depends on the known x_<i>, so one pass scores the point. Sampling
is serial: y_1 first, then y_2 needs y_1, and so on, D = 256
sequential steps. IAF (Inverse Autoregressive Flow) flips it:
sampling is one parallel pass, density eval is 256 serial steps.
Figure u04_f04_computational_asymmetry.png shows the table.

The idea: triangular structure gives cheap determinants but the
autoregressive dependency chains the computation in one
direction. The cheap direction is the one that follows the
dependency order. There is no flow with both directions parallel
and fully expressive: that is the fundamental tradeoff of the
family.

Computed example: D = 256. MAF density: 1 parallel pass. MAF
sampling: 256 serial steps. IAF: the reverse. These are step
counts, not wall times. Wall time depends on hardware, but serial
steps do not parallelize.

Variables, units, shapes, assumptions: D is the data dimension.
A "step" is one coordinate block evaluation. Assumption: the
conditioner networks dominate cost equally in both directions.

Mechanism: y_i = x_i x s_i(x_<i>) + t_i(x_<i>). Given all of x,
every s_i and t_i computes at once: density is parallel. Given
only noise, y_1 is known first, then s_2, t_2 need y_1: sampling
is serial.

Code:

    # MAF sampling sketch: serial loop, cannot vectorize over i
    y = np.zeros(D)
    for i in range(D):
        y[i] = z[i] * s[i](y[:i]) + t[i](y[:i])

Check: count the loop iterations. They equal D. That is the
asymmetry, visible in the code shape.

Cost: serial direction costs D sequential conditioner calls.
Parallel direction costs 1 batched call.

Alternatives: coupling layers (parallel both ways, weaker per
layer). Continuous flows (ODE solver cost instead). Choose MAF
when scoring dominates (density estimation), IAF when sampling
dominates (generation).

Failure case: training a MAF for a generation workload. Sampling
is 256 serial steps per point. Throughput dies. The model is
correct and unusable. Match the flow to the workload direction.

Research reading: autoregressive flow texts (background).
Falsifiable extension: time MAF sampling versus IAF sampling at D
= 256 on the same hardware with the same conditioner size.
Confirm the serial direction is slower by roughly the predicted
factor.

## C11, expressivity

Motivating question: one affine layer, one Gaussian base. What laws
can it never reach?

Start from zero. x = 2z + 1 with z ~ N(0,1) is N(1, 4). Always.
Any affine map of a Gaussian is a Gaussian: unimodal, symmetric in
the whitened coordinates, one mode. The two-mode target 0.5 N(-3,1)
+ 0.5 N(3,1) has two modes. No choice of slope and intercept fits
both. The script's 20,000 samples have mean 1.0 and variance 4.03:
a Gaussian, as theory demands.

The idea: one layer has the expressivity of its function class. An
affine layer gives affine images of the base. Stacking layers
composes maps: two affine layers are still affine, so depth alone
does not help without nonlinearity between or inside layers.
Coupling layers with neural s and t are universal approximators in
the large-depth limit, but each finite stack has finite reach.
Expressivity is a property of the composed map, not a vibe.

Computed example: the N(1, 4) result. Proof sketch: the
characteristic function of an affine image is the base
characteristic function composed with an affine argument. A
Gaussian characteristic function stays Gaussian. Two modes would
need a non-Gaussian characteristic function. Contradiction.

Variables, units, shapes, assumptions: the base is Gaussian. The
map is affine. Assumption: "cannot fit" means exactly. Approximate
fits (one wide Gaussian over two modes) exist and are bad.

Mechanism: affineness is preserved under composition. Nonlinearity
must enter through s, t, or activation functions to break the
Gaussian family.

Code:

    xsamp = rng.standard_normal(20000) * 2.0 + 1.0
    print(xsamp.mean(), xsamp.var())  # 1.0 4.03

Check: a unimodality test (Hartigan dip) on the samples fails to
reject. The samples are Gaussian.

Cost: conceptual. The practical cost is poor fit from too few
or too linear layers.

Alternatives: deeper stacks with nonlinear conditioners. Mixture
bases. Non-affine couplings (splines). Use depth plus
nonlinearity when the target is multimodal.

Failure case: a single affine layer on multimodal data. The fit
covers both modes with one wide Gaussian (forward KL behavior,
U02-C07). Samples fall between the modes, where the truth has a
valley. The likelihood looks acceptable. The samples are wrong.

Research reading: flow expressivity texts (background).
Falsifiable extension: fit 1, 2, and 4 coupling layers to the
two-mode toy with matched budgets. Plot held-out likelihood
versus depth. Confirm the single affine layer plateaus far below.

## C12, numerical constraints

Motivating question: the math is exact. The floats are not. Where
does it break?

Start from zero. A stack of 100 layers, each with diagonal factor
1e6. The determinant is (1e6)^100 = 1e600. float64 overflows at
1e308. np.prod returns inf. The log-determinant is 100 x log(1e6)
= 1381.55. Finite, exact, boring. The script prints both: inf and
1381.55. Work in log space or drown.

The idea: determinants multiply across layers and dimensions. Logs
add. Linear-space determinants overflow or underflow on any deep
stack. The log-det is the native quantity: the likelihood needs
it, the gradient needs it, nothing needs the raw determinant. A
second constraint: the condition number. diag(1e6, 1e-6) has
condition number 1e12. Inverting it amplifies rounding error by
1e12. The inverse direction of such a layer is numerically
fiction.

Computed example: inf versus 1381.55 above. Condition number 1e12
for the toy diagonal. Double precision has 16 digits. 1e12 eats 12
of them. Four digits of accuracy remain.

Variables, units, shapes, assumptions: float64. log-det in nats.
Assumption: the diagonal entries are bounded away from zero and
infinity in log space. Enforce it with exp/softplus
parameterization.

Mechanism: log turns products into sums. Sums do not overflow.
The condition number bounds the relative error amplification of
the inverse.

Code:

    logdet = np.sum(np.log(np.full(100, 1e6)))
    print(logdet)  # 1381.55, finite

Expected output: 1381.55.

Check: assert all log-det contributions are finite before summing.
A single inf poisons the likelihood silently.

Cost: one log per diagonal entry. Negligible.

Alternatives: float128 (delays the problem, halves speed).
Rescaling layers (keeps factors near 1). ActNorm-style
data-dependent init. Use log space always, rescaling when factors
drift.

Failure case: NaN likelihoods mid-training. The usual cause is a
log-det that went to -inf (a diagonal hit zero) or +inf
(explosion). Guard: clamp the log-scale outputs of s networks and
monitor the log-det range per layer.

Research reading: numerical linear algebra texts (background).
Falsifiable extension: train a 20-layer toy flow with and without
log-space accumulation. Record the step at which the linear-space
version NaNs. Report it.
