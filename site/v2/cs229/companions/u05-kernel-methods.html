Section 1 · SL-01 · C01

Feature maps: change the input, keep the model

From the lessonSL-01 §Source anchor, §Mental model

House price curves with living area. A line underfits. How do we fit a cubic while keeping the linear machinery? Map the input attribute x to a feature vector φ(x) that lists the nonlinear terms, then fit a linear model in the features. The cubic is linear in [1, x, x², x³]. The model did not change. The input did.

From the lessonSL-01 §Correctness checks, §Failure case

Two checks. φ(x) keeps a fixed length for every x. The prediction is linear in θ, nonlinear in x. The failure case: a degree-20 map on 25 points. The features memorize (U02 SL-06). The map adds capacity. It does not add wisdom.

Nugget 1 · From the lessonSL-01 §Mental model

The model did not change. The input did. Nonlinearity entered through the features, and all the linear theory survived.

Why it matters companion
Reusing proven machinery beats rebuilding it. The feature map is an adapter: new shapes in, old guarantees out.
Transfer companion
When the tool cannot bend, bend the input. Adapters are cheaper than new tools.

Section 2 · SL-02 · C02, C03, C04

The kernel trick: never write the map down

From the lessonSL-02 §Source anchor, §Mental model

The cubic map in d = 1000 dimensions has about 1e9 entries. Can we fit the cubic without ever writing it down? Start θ at 0. Every LMS update adds a multiple of some φ(x⁽ⁱ⁾). So θ always equals Σᵢ βᵢ φ(x⁽ⁱ⁾): a combination of training feature vectors. Predictions need only inner products φ(x)ᵀφ(z). Define K(x, z) as that inner product and never form φ.

From the lessonSL-02 §Derivation

Write θ = Σⱼ βⱼ φ(x⁽ʲ⁾). The update on the coefficients: βᵢ := βᵢ + α (y⁽ⁱ⁾ − Σⱼ βⱼ K(x⁽ⁱ⁾, x⁽ʲ⁾)). In vector form with K the Gram matrix: β := β + α (y − Kβ). Prediction at x: θᵀφ(x) = Σᵢ βᵢ K(x⁽ⁱ⁾, x) (notes pages 53 to 54). For φ listing all monomials of degree at most 3: K(x, z) = 1 + ⟨x,z⟩ + ⟨x,z⟩² + ⟨x,z⟩³ (notes page 53). Cost: O(d) for the inner product, not O(d³) for the features.

From the lessonSL-02 §Minimal implementation, §Correctness checks

The lesson's Gram matrix on X = [[1, 2], [3, 1]] with the degree-3 polynomial kernel: K = [[216, 216], [216, 1331]], since (1 + 5)³ = 216 and (1 + 10)³ = 1331. Beta LMS converges toward K⁻¹y. Two checks: K(x, x) ≥ 0 always, and β LMS must converge to the same predictions as primal LMS on small explicit features.

Nugget 2 · From the lessonSL-02 §Failure case

β has length n, not p. The dual trades feature dimension for sample size: it wins when p is much larger than n and loses when n is much larger than p.

Why it matters companion
The trick is not free. It moves the cost from the feature count to the example count. With 1e6 examples the Gram matrix is 1e12 entries, and the trick becomes the problem.
Transfer companion
Every dual representation swaps which size hurts. Name both sizes before you choose sides.

Section 3 · SL-03 · C05, C06, C07

Valid kernels: symmetry, PSD, Mercer

From the lessonSL-03 §Source anchor, §Mental model

The Gram matrix Kᵢⱼ = K(x⁽ⁱ⁾, x⁽ʲ⁾) holds all pairwise similarities. If K comes from some φ, K is symmetric (inner products commute) and PSD: zᵀKz = Σₖ (Σᵢ zᵢ φₖ(x⁽ⁱ⁾))² ≥ 0. Mercer says the converse holds: symmetric PSD on every finite point set means some φ exists, possibly infinite-dimensional.

From the lessonSL-03 §Composition rules, §Correctness checks

Composition rules: sums, products, and positive scalings of valid kernels are valid. exp(K) is valid. This builds new kernels from old ones without re-proving Mercer each time. Two checks before trusting any kernel: symmetry, max |K − Kᵀ| near zero. PSD: smallest eigenvalue ≥ −1e−8 of numerical tolerance. K(x, x) > 0 for distinct-feature kernels.

Illustration The kernel auditor. Pick a candidate: the Gaussian kernel, the lesson's polynomial identity terms, or the invalid K(x, z) = x − z. The toy builds the Gram matrix on {0, 1, 2} and runs the lesson's two checks.

A hand-made similarity that is not PSD makes the dual objective non-convex. Test PSD before trusting a custom kernel.

Nugget 3 · From the lessonSL-03 §Failure case

Not every similarity is a kernel. A hand-made similarity that is not PSD breaks convexity, and the solver can diverge.

Why it matters companion
The kernel certificate is a contract with the optimizer. Without it the math that justifies the algorithm stops applying, silently.
Transfer companion
Check the precondition, not just the output. The two cheapest tests in this unit, symmetry and PSD, prevent the most expensive failure.

Section 4 · SL-04 · C08 to C12

Geometry, costs, and limits

From the lessonSL-04 §Nonlinear geometry

A linear boundary in feature space is a curved boundary in input space. The Gaussian kernel draws smooth blobs around training points. The polynomial kernel draws algebraic curves. The kernel chooses the curve family.

From the lessonSL-04 §Computational cost

Gram matrix: O(n²) kernel evaluations, O(n²) memory. Kernelized LMS per sweep: O(n²). Prediction per query: O(n). The dual wins when the implicit dimension p is much larger than n and loses when n is huge. 1e6 examples need 1e12 Gram entries. Remedies: subset methods, random features, or primal SGD on explicit features.

Illustration The arithmetic judge. Type n, d, and the degree. The toy estimates Gram entries, memory, one dual sweep, and the primal sweep, then names the winner by the lesson's rule.

n: d: degree:

Explicit features p ≈ C(d + degree, degree). Primal sweep O(np). Dual sweep O(n²). Memory n² × 8 bytes.

From the lessonSL-04 §Regularization, §Feature scaling, §Limitations

Kernel methods still overfit. The Gaussian kernel with tiny σ memorizes: each point its own blob. Control: ridge on β (add λI to K), or pick σ by validation. Regularization is not optional in infinite-dimensional spaces. The failure case with a number: Gaussian kernel, σ = 1e−6, no regularization. K is numerically the identity, β = y, train error 0, test error huge. The kernel did exactly what was asked.

Feature scaling rules the Gaussian kernel. K(x, z) = exp(−‖x − z‖²/(2σ²)) is ruled by raw distances. A feature in dollars versus a feature in cents gets 1e4 times the weight. Standardize first, then pick σ on the standardized scale. And three limits to carry: no feature weights to inspect, the model is a sum over examples, so interpretability suffers. Prediction cost grows with n: every query touches all support points. Kernel choice is a prior, the wrong kernel is a wrong model, and validation is the only honest selector.

Nugget 4 · From the lessonSL-04 §Computed cost example

Choose by arithmetic, not habit. At n = 10,000 and d = 20, the primal sweep is 1.8e7 operations against the dual's 1e8. The dual loses.

Why it matters companion
Elegant methods seduce. The Gram matrix at 800 MB is not elegant. Count first, admire second.
Transfer companion
Put the cost estimate before the method choice. Two multiplications beat a page of theory.

Nugget 5 · From the lessonSL-04 §Failure case

Tiny σ memorizes. K becomes the identity, β becomes y, train error hits 0, and the test error explodes. The kernel did exactly what was asked.

Why it matters companion
Memorization is not a malfunction. It is the method working as specified with a bad specification. The specification is yours.
Transfer companion
When a method can memorize, assume it will until regularization says otherwise. Capacity without a leash is a liability.

Section 5 · Synthesis

The arc, end to end

From the lessonSL-01 to SL-04

The arc, end to end. Map the input to richer features and the linear machinery survives: a cubic in x is linear in [1, x, x², x³] (SL-01). Then erase the map. θ always equals Σᵢ βᵢ φ(x⁽ⁱ⁾), predictions need only inner products, and K(x, z) = 1 + ⟨x,z⟩ + ⟨x,z⟩² + ⟨x,z⟩³ computes in O(d) what the features would cost in O(d³) (SL-02).

Not every function of two arguments earns the name kernel. Symmetric PSD on every finite point set is the certificate, and Mercer says it is also sufficient (SL-03). Sums, products, and positive scalings of valid kernels stay valid. Then the bill: O(n²) memory, O(n²) per sweep, O(n) per query, and a dual that wins only when the implicit dimension dwarfs n (SL-04). Regularize, standardize, validate the kernel choice, and never trust a custom similarity without the PSD test.

From the lesson§Research reading, §Nearest alternatives

Where the unit points next, in the lesson's own forward links. Random Fourier features: explicit features, but approximate. Deep networks (U07) learn the feature map instead of fixing the kernel: more data-hungry, less principled at small n. The string kernel (notes page 59) classifies text without ever writing the 26^k feature vector. The extension: on the ring dataset, compare test error of polynomial degrees {2, 4, 8} and Gaussian σ across a grid, with ridge. The falsifiable claim: the best Gaussian beats the best polynomial, and both beat the linear model.
