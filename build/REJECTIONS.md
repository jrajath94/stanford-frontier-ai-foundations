# REJECTIONS — what Raj rejected, and what to do instead
# Required reading for every agent, before any work. Updated 2026-10-06.
# Each pattern below is a real rejection from Raj. Do not repeat it.

1. SUMMARIES INSTEAD OF TEXTBOOK → Write the narrative chain
   (problem → attempt from zero → break demonstrated → hinge question →
   new idea from zero → map back → honest price). Never summarize.
2. NO CHAINING FROM ZERO → 0 → 0.1 → 0.12 → 1. Every term defined at
   first use. Each subchapter adds exactly one increment. Split any
   subchapter that introduces two ideas.
3. MISSING VARIANTS → Cover the full family, each with a worked toy
   or number. The reader must think from multiple dimensions.
4. NO WHAT'S-USED-WHERE → Map every mechanism to real models
   (GPT, Gemini, DeepSeek, Llama, Mistral, Mamba). Verify against
   public sources current as of October 2026. Non-public = unknown.
5. NO SUBCHAPTERS → ### subchapters in every substantial section,
   one idea each. Knowledge-base hierarchy: index → lecture →
   subchapters.
6. DIFFICULTY JUMPS → Never 0 → 0.5 → 1. Audit step sizes.
7. STALE DATA → Every model fact verified as of October 2026.
8. MISSING VIDEOS/LINKS → youtube-nocookie embeds (verified IDs) +
   live go-deeper links on EVERY page.
9. FLUFF → Every paragraph carries a number, mechanism step, failure
   mode, or decision rule. Cut only zero-information sentences.
10. BREADTH OVER DEPTH → Interviews test depth. Go deeper on the core
    mechanism instead of adding variants.
11. THIN CRASH COURSES → Potency bar: reading the crash course alone
    = interview-ready. Multi-chapter, memory aids, 25+ question exam
    test at 100%.
12. CONTENT CUT TOO SHORT → Expansion first: every concept, angle,
    number, example. NEVER cut substance to save space. Short ≠ dense.
13. MISSING/NON-COMPLIANT IMAGES → Page audit per page; spec is law;
    medium ladder; lesson + chapter plates; reject list enforced.
14. MESSY REPOS → Only the latest version of every file. Delete
    superseded files. Clean trees.
15. GIT NOT SYNCED → Push everything (new + changed, hash-compared).
    Verify remote counts. Never leave local work unpushed.

# How to use this file
Before writing a word, ask: "which of these 15 am I about to commit?"
If the answer is not "none," stop and fix the plan.
